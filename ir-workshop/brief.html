Incident brief

A ransomware attack against IROrg. Read this before you start. It is the scenario, the evidence the SOC has gathered, and exactly what your team needs to produce.

ScenarioEvent timeline IndicatorsAffected assets NIST phasesYour objective What to produce

Scenario

IROrg runs a Windows domain that supports core business services. Its central file server, srv-web01.irorg.local, holds shared departmental documents, archived records, and active project materials. The environment has endpoint protection and a central SIEM for monitoring.

The SOC starts receiving a burst of high severity alerts from multiple endpoints within a short window. That pattern points to coordinated activity rather than isolated events. Soon after, staff report that shared folders on srv-web01 are inaccessible and files now carry an unfamiliar .df_locked extension, with a ransom note demanding cryptocurrency payment.

What the SOC sees
  • Suspicious binaries executed from user TEMP directories
  • Encoded PowerShell activity on user workstations
  • Multiple outbound connections to unfamiliar external infrastructure
  • Administrative authentication originating from a user endpoint
  • Windows event logs cleared on a compromised host
  • Rapid spike in file modifications on the central file server
  • Endpoint protection detections on staging binaries
Impact. Shared folders on srv-web01 are encrypted with the .df_locked extension and a ransom note demands payment. The backup server is inactive and cannot be relied on for recovery.

The NIST incident handling phases

Record each phase as a case task in TheHive. Here is what each one means.

1Detection

Confirm the security incident using the incident detection details already provided in the brief.

2Analysis

Investigate and analyse the incident details to understand what happened, its scope, and its impact.

3Containment

Limit the incident to prevent further spread or damage.

4Eradication

Remove the threat and fix the vulnerabilities that allowed it to occur.

5Recovery

Restore affected systems and services to normal operation and monitor for any recurrence.

6Post Incident Activity

Review what happened, capture lessons learned, and improve future incident response.

Your objective

Respond as IROrg’s internal incident response team using the four tools, following the NIST incident handling phases and recording each phase as a case task in TheHive. The response actions are yours to decide; the case facts are above.

  1. Coordinate with your team in Mattermost.
  2. Create a case in TheHive with an appropriate title.
  3. Add six case tasks named after the NIST phases and document your response actions in each.
  4. Add the provided indicators as observables, plus any artifacts you extract.
  5. Record the IoCs in MISP and correlate any new ones you find.
  6. Analyse observables in Cortex (VirusTotal, AbuseIPDB, and others).
  7. When every task is done, close and resolve the case in TheHive.

What to produce

  • A case with an appropriate title.
  • Six case tasks, each titled after a NIST phase, each with a short summary of what your team did.
  • All provided indicators added as observables, plus any extra artifacts you extract.
  • The case closed and resolved once every task is complete.
  • An event with an appropriate title.
  • Every scenario IoC recorded, plus any new ones you discover.
  • Each attribute filed under the correct category such as Network Activity, Payload Delivery, or Malware Hash.
  • Each observable analysed with relevant analysers such as VirusTotal or AbuseIPDB.
  • A short summary of key findings added to the matching case task in TheHive.
  • Discussion in your team channel from the first alert through to resolution.
